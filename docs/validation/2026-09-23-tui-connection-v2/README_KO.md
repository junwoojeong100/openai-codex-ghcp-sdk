## 반복 끊김에서 확인한 사실

최초 실행의 Haiku U12에서 `api.enterprise.githubcopilot.com/v1/messages` 연결이 SDK 자체 재시도 5회 이후 `ETIMEDOUT`으로 실패했습니다. 같은 시간대 다른 26건은 시작 단계에서 실패했습니다. 당시 시작 오류는 어느 SDK 작업에서 실패했는지 표시하지 않았으므로, 26건 각각의 근본 원인까지 확정한 것은 아닙니다. 이 실패들을 지우거나 통과로 재분류하지 않았습니다.

별도의 사용자 대화에서는 브릿지 자동 복구 1회 소진 오류가 발생했습니다. 실행 중인 `/health`에서 무진행 제한 90초·복구 1회·감시 15초를 확인했으므로 복구 기능은 켜져 있었습니다. 위 연결 실패는 격리된 실검증에서 얻은 증거이며 사용자 대화의 정확한 원인까지 입증하지는 않습니다. 로컬 SDK ping 성공은 원격 모델 서비스 연결 성공을 보장하지 않습니다.

두 번째 실행 전에 Copilot 엔드포인트의 HTTPS 연결이 다시 응답했습니다. 운영 watchdog·케이스 제한 시간·판정 조건을 완화하지 않고 72건 전체를 다시 실행해 통과했습니다. 코드가 네트워크를 복구했다거나 향후 상위 서비스 장애까지 제거했다는 뜻은 **아닙니다.**

## 개선 사항과 증거

v2는 모든 케이스에서 `session.rpc.model.getCurrent()`의 실제 모델 상태, 컨텍스트 tier·catalog 일치, Responses SSE 완료, 실제 watchdog 설정을 확인합니다. U03은 자격 증명처럼 보이는 `token` 대신 프롬프트에 없는 합성 `sample_id`를 도구로 읽습니다. 기대와 다른 답변으로 완료되면 무응답 시간 초과로 오인하지 않고 즉시 실패시킵니다. 실패 전 관측값도 보존하며, 대기 중 TUI는 불필요한 프로세스 그룹 신호 대신 `/quit`으로 정상 종료하고 종료 대기 타이머를 해제합니다.

이번 연결 문제를 계기로 시작 실패 시 `start`·`ping`·`listModels` 중 실패 지점을 내용 없는 진단으로 남기고, 무응답 오류에 설정된 제한·마지막 루트 진행 이벤트를 표시하도록 개선했습니다. 진행을 위장하거나 접수 불명 도구 결과를 재제출하거나 기본 제한을 늘리지는 않았습니다. [문제 해결 문서](../../../README_KO.md#제한과-문제-해결)의 지연 허용 실행 설정은 선택 사항이며 두 점수 산정 실행에서는 **사용하지 않았습니다.**

최종 실행에는 **모델 usage 126건, 완료 응답 스트림 126건, SDK 실제 모델 상태 113건, 프로세스 표본 828건**이 기록됐습니다. **실패 스트림·무응답 턴·자동 턴 복구·SDK 세션 정리 오류·남은 프로세스·남은 임시 catalog는 모두 0건**입니다. Copilot 런타임 아래 MCP 프로세스도 없었습니다. U08은 6개 모델 모두 Escape 취소 후 같은 프로세스에서 다음 요청에 응답했습니다.

Codex의 선택적인 자동 제목 생성은 계속 미지원입니다. 정확한 제목 스키마의 **HTTP 400 거절 102건**을 별도 집계했으며 성공한 모델 응답으로 인정하지 않았습니다. 다른 HTTP 오류와 실패 스트림은 계속 실패 판정 대상입니다.

관련 단위·판정 검사와 **실제 Codex + SDK 대역 runtime 14건**도 통과했습니다. 무응답 복구·바이트 전용 진행·설정 제한·120회 도구 호출·모델/추론 수준 변경·새 대화 정리를 포함합니다. 오프라인 검사를 실검증 점수에 합산하지 않습니다.
