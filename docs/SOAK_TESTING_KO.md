# 실제 Codex 장기 대화 내구성 검증

[English](SOAK_TESTING.md) · [검증 안내](../README_KO.md#개발과-검증) · [TUI 시나리오](TUI_SCENARIOS_KO.md) · [검증 기록](validation/README_KO.md)

두 러너가 시간에 따른 동작을 검사합니다.

- **`test:terminal`**은 한 모델을 실제 가상 터미널(PTY)에서 정해진 작업량으로 실행합니다. 화면은 독립 파서나, xterm.js로 렌더링하는 브라우저가 읽습니다. 데스크톱 터미널 앱은 검사하지 않습니다.
- **`test:soak`**은 오래 유지되는 네이티브 대화를 실행하며, 터미널 lane을 추가할 수 있습니다.

둘 다 66건 안정성 행렬을 대신하지 않습니다. 기록된 결과는 [검증 기록](validation/README_KO.md#기록된-결과)에 있습니다.

| 목적 | 시작할 곳 | 실모델 호출 |
| --- | --- | --- |
| 실행 없이 작업 내용 확인 | [계획](#계획) | 없음 |
| SDK 대역으로 두 터미널 드라이버 검사 | [오프라인 runtime](#오프라인-runtime) | 없음 |
| 한 모델을 정해진 시간 동안 실행 | [터미널 검사](#재현-가능한-터미널-검사) | **있음** |
| 여러 모델의 짧은 작업 확인 | [실모델 smoke](#짧은-실모델-smoke) | **있음**(`--smoke`도 호출) |
| lane마다 최소 5시간 실행 | [5시간 실모델 실행](#5시간-실모델-실행) | **있음**(지속적으로 사용) |

각 모드는 단독으로 실행할 수 있으며 오프라인 검사와 smoke 실행은 선택 사항입니다. 실행한 뒤에는 [보고서를 읽으세요](#결과-읽기).

## 준비 사항과 오프라인 검사

### 계획

Codex·Python·Chromium·Copilot 로그인이 필요하지 않습니다. `npm ci` 후 저장소 루트에서 실행합니다.

```sh
npm run test:terminal -- --plan --driver playwright
npm run test:soak -- --plan
```

### 실행 준비 사항

실행·runtime 검사에는 **Node 22.12 이상과 Codex 0.154.0**([설치 단계](../README_KO.md#2-의존성-설치))이 필요하고, 터미널 경로에는 **Python 3**도 필요합니다. Chromium은 Playwright 드라이버와 터미널 runtime 검사에만 필요합니다.

```sh
npx --no-install playwright install chromium
```

Linux 라이브러리 오류는 [Chromium 설치 안내](TUI_SCENARIOS_KO.md#실행-준비-사항)를 참고하세요. 오프라인 검사에는 Copilot 로그인이 필요하지 않습니다.

### 오프라인 runtime

실제 Codex와 SDK 대역(Copilot SDK 대신 동작하는 로컬 구현)으로 두 터미널 드라이버를 검사합니다. 모델을 호출하지 않습니다.

```sh
npm run test:terminal:runtime
```

## 재현 가능한 터미널 검사

**Copilot 사용량이 발생합니다.** [실행 준비 사항](#실행-준비-사항)을 설치하고 [Copilot 계정 확인](../README_KO.md#3-설치와-계정-접근-확인)을 마치세요. 아래 드라이버 중 **하나**를 고르고 실행마다 새 출력 디렉터리를 사용합니다.

`test:terminal`은 `--model`로 모델을 선택합니다. 실행기의 `--ghcp-model`은 여기에 적용되지 않습니다.

**PTY 드라이버**, 실측 대화 120초:

```sh
npm run test:terminal -- --execute --driver pty --model gpt-6-astra \
  --duration-seconds 120 --output .runtime/terminal-pty-new
```

**또는 Playwright 드라이버**, 더 큰 입력·출력:

```sh
npm run test:terminal -- --execute --driver playwright --model claude-sonnet-5 \
  --duration-seconds 120 --payload-bytes 24576 --response-words 1000 \
  --output .runtime/terminal-browser-new
```

- `--duration-seconds 120`은 **준비 완료 이후** 최소 120초의 실측 대화를 뜻하며 명령 전체의 제한 시간이 아닙니다. 준비·마지막 진행 중 턴·정리 시간이 더해집니다.
- `Ctrl+C`나 `SIGTERM`은 작업을 취소하고 부분 실행을 미완료로 남깁니다.
- 옵션 범위와 통과 기준은 [터미널 작업과 증거](#터미널-작업과-증거)를 참고하세요.

## 통합 soak 러너

두 모드 모두 GPT-6 Luna와 Claude Sonnet 5의 **lane**(독립적으로 감시하는 대화) 두 개를 시작합니다. `./bin/ghcp-models`로 `gpt-6-luna`와 `claude-sonnet-5`를 사용할 수 있는지 확인하세요. 실행기 기본 모델인 Astra에 대한 접근만으로는 부족합니다. `--terminal`은 별도의 Luna TUI lane을 추가합니다.

짧은 smoke와 5시간 실행 중 하나를 고르세요. smoke 실행은 사전 조건이 아닙니다.

### 짧은 실모델 smoke

**Copilot 사용량이 발생하며 오프라인 검사가 아닙니다.** 실제 GPT-6 Luna와 Claude Sonnet 5를 호출합니다. [실행 준비 사항](#실행-준비-사항)과 [Copilot 계정 확인](../README_KO.md#3-설치와-계정-접근-확인)을 마친 뒤 새 출력 디렉터리를 사용하세요.

```sh
npm run test:soak -- --smoke --duration-seconds 60 --output .runtime/soak-smoke-new
```

smoke 시간은 1–600초를 허용하며 내구성 결과로 인정하지 않습니다. 새 실행에 터미널 lane을 추가하려면 PTY는 `--terminal`, 브라우저 렌더링은 `--terminal --terminal-driver playwright`를 붙입니다.

### 5시간 실모델 실행

**Copilot 사용량이 지속적으로 발생합니다.** 선언한 모든 lane이 준비 완료 이후 최소 18,000초를 실측해야 하며 준비·정리 시간이 더해집니다. 먼저 [실행 준비 사항](#실행-준비-사항)과 [Copilot 계정 확인](../README_KO.md#3-설치와-계정-접근-확인)을 마치세요.

```sh
npm run test:soak -- --execute --output .runtime/soak-five-hours-new
```

- 출력 디렉터리는 매번 새로 지정해야 합니다.
- 러너는 실행 전에 소스의 동결 사본을 저장하고 그 사본으로 worker를 실행합니다. 개발 파일을 수정해도 실행 중인 worker는 바뀌지 않습니다.
- `frozenSourceUnchanged`는 실제로 실행된 코드를 확인하고, `implementationUnchanged`는 개발 작업 트리가 바뀌었는지를 따로 보고합니다.
- 어떤 결과도 66건 행렬에 더하거나 행렬을 재채점하지 않습니다.

## 결과 읽기

출력 디렉터리의 `report.json`(예: `.runtime/soak-smoke-new/report.json`)을 읽으세요. 두 러너에는 `--verify` 명령이 없습니다.

| 실행 | 확인할 필드 | 통과의 의미 |
| --- | --- | --- |
| `test:terminal -- --execute` | `passed: true` | 지정한 단기 작업·시간·증거·정리 조건 충족. 5시간 내구성은 아님 |
| `test:soak -- --smoke` | `allLanesCompleted`·`noObservedFailures`·`frozenSourceUnchanged`가 모두 `true` | 짧은 작업 통과. 최상위 `durationMet`는 의도적으로 `false` 유지 |
| `test:soak -- --execute` | 위 세 필드와 `durationMet: true` | 모든 lane에서 관측된 실패 없이 최소 5시간 충족. 최대 문맥 인증은 아님 |

| 종료 코드 | 의미 |
| --- | --- |
| 0 | 유효한 계획, 또는 선택한 모드의 통과 |
| 1 | 실패·미완료 실행 |
| 2 | 인자 또는 러너 오류 |

smoke 통과도 내구성 통과가 아닙니다. 실행이 중단됐다면 새 실행을 시작하기 전에 기존 보고서를 읽으세요.

## 터미널 작업과 증거

아래는 위 터미널 검사에 대한 설명이며 추가로 실행할 명령이 아닙니다.

| 옵션 | 허용 범위 | 의미 |
| --- | --- | --- |
| `--duration-seconds` | 1~86,400초 | `test:terminal`의 최소 실측 대화 시간이며 5시간 인증은 아님. 마지막 진행 중 턴에는 별도 제한 시간 적용. |
| `--payload-bytes` | 128~65,536바이트 | 생성할 입력 크기. |
| `--response-words` | 0~3,000단어 | 요청할 출력 길이. 0이면 완료 표식만 요청하며, 실제 출력이 선언한 최소 문자 분량을 충족해야 함. |
| `--model` | [지원 ID 6개](../README_KO.md#모델) | 계정에서 사용 가능해야 하며 자동 대체하지 않음. |

- 두 드라이버는 같은 전용 PTY 수명주기·작업·성공 기준을 사용합니다. Playwright는 브라우저로 프롬프트와 Escape를 보내고, xterm.js가 터미널 렌더링과 질의 응답을 처리합니다.
- 고유한 완료 표식은 정확한 모델 식별 정보와 함께 관측된 루트 SDK 응답에도 나타나야 합니다. 터미널에 보이는 텍스트만으로는 부족합니다.
- 필터 신호·SDK 오류·실패한 SSE·짧거나 없는 응답·시간 초과·정리 실패는 실패로 남습니다.
- 출력 디렉터리에는 보고서, heartbeat, SDK·HTTP 요약, 터미널 receipt가 남고 브라우저 드라이버는 스크린샷도 남깁니다. 소스 사본에는 HTML과 Python 파일도 포함됩니다.
- 생성한 비민감 데이터만 보냅니다. 실행마다 자체 `HOME`·`CODEX_HOME`·작업 디렉터리·bridge를 사용하며, 샌드박스는 읽기 전용을 유지하고 도구 승인을 우회하지 않습니다. 실모델 자식 환경에는 SDK에 필요한 인증·프록시 설정만 남깁니다. 브라우저는 공개 서비스를 열지 않고 비어 있는 전용 프로필을 사용합니다.
- 취소하면 감독 프로세스가 터미널 worker에 PTY와 브라우저를 정리할 제한된 시간을 준 뒤 강제 종료 단계로 넘어갑니다.
- 입력 데이터는 시작할 때 하루치를 한꺼번에 만들지 않고 다음 턴에 필요한 만큼만 생성합니다. 터미널 파서는 Codex의 스크롤 영역을 반영하므로 긴 답변도 입력창을 다시 그릴 때 마지막 표식을 잃지 않습니다. 터미널이 종료된 뒤 증거 파일을 닫기 전에, 늦게 도착하는 브라우저 입력 callback을 비활성화합니다.

## 오프라인 회귀 검사 범위

`npm run test:context:runtime`은 기계적인 SDK 대역으로 다음을 검사합니다.

- 네이티브 도구 호출 120회 연속, 반복 압축, 무응답 제한·설정 제한 초과·Escape 뒤 같은 TUI에서의 복구. 예상한 오류 케이스는 실제 오류 줄과 다음 프롬프트의 성공이 필요하며, 터미널을 다시 시작하는 것은 인정하지 않습니다. 화면을 다시 그리는 것만으로는 준비 완료나 완료로 보지 않습니다.
- 운영 제한값(첫 진행 180초, 스트리밍 90초)에서 첫 진행을 **실측 95초** 지연하는 검사. SDK 세션 1개, 프롬프트 제출 1회, 복구 없음, 후속 턴 성공이 필요합니다.
- 무응답 턴 복구, 바이트만 늘어나는 진행과 루트 단계 진행. 비공개 단계 내용은 노출하지 않습니다.

제한된 SDK 대역 회귀 검사이며 원격 모델 가동 시간이나 최대 문맥 인증이 아닙니다.

## 네이티브 작업

- **GPT-6 Luna:** 실제 모델 catalog가 알리는 최대 문맥 등급의 입력 예산과 자동 압축을 사용하는 지속 대화입니다. 매 턴 새로 갱신한 8 KiB 비활성 합성 데이터를 네이티브 도구로 읽고 sample 식별자를 반환합니다.
- **Claude Sonnet 5:** 같은 작업에 **131,072 토큰 클라이언트 문맥 설정**, 98,304 토큰 자동 압축, 성공한 40번째 턴 슬롯마다 명시적 네이티브 압축을 적용합니다. 이는 가속한 클라이언트 문맥 스트레스이며 공급자 최대 문맥을 시험했다는 뜻은 아닙니다.
- **선택적 터미널 lane:** `--terminal`은 GPT-6 Luna의 실제 Codex TUI를 추가하고 65,536 토큰 클라이언트 설정을 명시합니다. 기본 `pty`는 독립 터미널 파서, `--terminal-driver playwright`는 headless xterm.js를 사용합니다. 터미널 결과와 app-server 결과는 별도 범위입니다.

- 턴은 보통 최소 25초 간격으로 시작합니다.
- fixture·`HOME`·`CODEX_HOME`은 검사가 소유합니다. 네이티브 thread는 읽기 전용이며, 예상하지 않은 도구는 거절하고 승인 요청은 거부합니다. 사용 중인 사용자 bridge·설정은 재시작하거나 바꾸지 않습니다. 운영 요청·턴·작업별 정리 기본값은 그대로 적용합니다.
- 새 sample은 순번으로 알리며, 숨은 식별자는 도구 callback으로만 알 수 있습니다. 초기 smoke 실행에서 모호한 동일 요청에 모델이 이전 sample을 재사용하는 문제가 드러났습니다. 그 실패는 기록에 남아 있으며, 이제 작업 지시가 sample이 바뀌었다고 알리고 현재 턴에서 한 번 새로 읽도록 요구합니다.

## 감시와 실패 증거

- **heartbeat와 로그:** worker는 5초마다 heartbeat를 쓰고 매 턴 네이티브·SDK 이벤트를 기록합니다. HTTP 요약은 계속 커지는 전체 요청 대신 바이트 수·hash·최종 SSE 유형·명시적 오류 코드를 남깁니다. 오류 사건은 민감정보를 제거한 로컬 증거를 남깁니다. 오래된 턴별 배열은 증거를 쓴 뒤에만 비우므로 관찰 버퍼가 계속 커지지 않습니다.
- **감독 프로세스:** 독립 감독 프로세스가 소유 worker와 자식 프로세스의 CPU·RSS를 15초마다 표본 추출합니다. heartbeat 정지와, 긴 모델 응답을 기다리는 살아 있는 worker는 다른 사건 유형입니다.
- **정지 판정 한도:** heartbeat가 120초 동안 없거나 한 네이티브 턴·압축이 480초를 넘으면, 감독 프로세스가 사건을 기록하고 해당 소유 worker 그룹만 단계적으로 종료합니다. 긴 응답 경고는 90초부터 시작하며, 경고가 교착 상태의 증거는 아닙니다.
- **예산:** 짧은 실행의 네이티브 host는 원래의 8 MiB transcript·1 MiB stderr 기본값을 유지합니다. 내구성 실행은 512 MiB transcript 예산, drain당 16 MiB stderr 예산, 디스크 기반 턴별 로그 drain을 사용합니다. 예산을 넘으면 조용히 자르지 않고 오류로 처리합니다.
- **재시도 없음:** 내구성 러너는 실패한 요청을 다시 시도하거나 성공으로 바꾸지 않습니다. bridge 자체의 출력 전 제한적 복구는 원래 요청 안에서 watchdog·복구 진단과 함께 일어나며 턴·요청 제한을 초기화하지 않습니다. 끝내 실패한 요청은 실패로 남습니다.
- **복구 thread:** 네이티브 세션이 실패하면 복구를 검사하려고 **새로 기록되는 thread**를 시작할 수 있지만, 실패한 턴은 그대로 집계합니다. 연속 3회 실패하면 조사를 위해 해당 lane을 멈춥니다. 정리 오류·알 수 없는 결과·미완료 시간은 그대로 보입니다.
- **보고서 필드:** 내구성 실행의 `durationMet`는 선언한 모든 lane에서 실제 5시간 이상이 필요합니다. 보고서는 성공·실패 턴, 활성 요청 시간, 전체 실측 범위, 관측된 최대 입력 토큰·이력 바이트·RSS, 압축 횟수, 복구 thread, 프로세스 그룹 정리를 따로 표시합니다. 간격 대기 시간은 모델 활성 시간이 아니며, 경과 시간만으로 최대 문맥에 도달했다고 볼 수 없습니다.

원시 증거는 Git에서 제외한 `.runtime` 디렉터리에 남습니다. 공개 전에 검토하고 민감정보를 가리세요. 네이티브 app-server 실행만으로는 대화형 터미널 렌더러를 검사했다고 볼 수 없으며, 터미널 PTY 범위는 별도로 표시하고 검증해야 합니다.
