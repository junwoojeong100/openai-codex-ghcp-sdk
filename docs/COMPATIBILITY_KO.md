# 호환성

[English](COMPATIBILITY.md) · [빠른 시작](../README_KO.md) · [사용법](USAGE_KO.md) · [구조](ARCHITECTURE_KO.md)

**텍스트 대화와 Codex가 직접 실행하는 도구는 지원하지만, OpenAI Responses API 전체를 지원하지는 않습니다.** 아래 표는 Codex CLI **0.154.0**과 Copilot SDK **1.0.14** 조합의 실사용 경계입니다. 모델을 사용할 수 있다고 모든 기능이 그 모델에서 동작하는 것은 아닙니다.

## 이 기능을 사용할 수 있나요?

| 작업 | 상태 | 상세 |
| --- | --- | --- |
| 대화, 로컬 파일 읽기·편집, 셸 명령 실행 | **지원** | Codex 자체 도구로 실행하며 Codex의 승인·샌드박스가 적용됩니다. 파일은 도구가 읽으며 모델에 첨부하지 않습니다. |
| `codex exec --json` 이벤트 수신 | **지원** | Codex가 JSONL 이벤트를 출력합니다. 모델 답변에 JSON 스키마를 강제하는 기능은 아닙니다. |
| Codex MCP 도구 사용 | **지원** | Copilot 런타임의 별도 MCP 서버는 계속 꺼져 있습니다. |
| 모델 전환·로컬 압축 | **지원** | [문맥 한도](USAGE_KO.md#모델-선택과-문맥) 안에서 동작합니다. |
| 저장된 대화 재개 | **지원** | Codex에 저장된 이력으로 재개합니다. 재시작한 bridge는 미해결 도구 호출을 복원하지 못합니다. [재개 동작과 모델 선택](USAGE_KO.md#대화-재개)을 참고하세요. |
| `apply_patch` 등 custom 도구 사용 | **근사** | 동작하지만 grammar는 모델에 대한 안내이며 생성 중에 강제되지 않습니다. |
| 이미지·오디오·영상·파일 직접 첨부 | **미지원** | 모델 입력과 도구 결과는 텍스트여야 합니다. |
| 스키마를 강제하는 JSON 출력 | **미지원** | 프롬프트로 JSON을 요청할 수는 있지만 스키마는 보장하지 않습니다. 자동 제목은 사용할 수 없으며, 이 형식이 필요한 네이티브 리뷰 요청도 실패합니다. |
| 공급자 호스팅 웹 검색 | **미지원** | 클라이언트 측 Codex MCP 도구와는 별개이며, Codex MCP 도구는 동작합니다. |
| WebSocket·원격 Responses 압축 | **미지원** | 실행기의 HTTP/SSE와 로컬 압축 기본값을 유지하세요. |

**지원은 프로토콜의 지원 범위이지 모든 모델의 작업 성공 보장이 아닙니다.** AGENTS·skill 지시 준수, 정확한 답변, 네이티브 Plan 질문과 MCP 호출 순서는 모델에도 달려 있습니다. HTTP/SSE 통신에 성공해도 작업 결과는 틀릴 수 있습니다. 목록의 사용 가능 표시만 보지 말고 [날짜가 명시된 결과](validation/README_KO.md#기록된-결과)를 확인하세요.

실행 오류는 [문제 해결](USAGE_KO.md#문제-해결)을 참고하세요. 이 페이지의 나머지는 개발자를 위한 프로토콜 참고 자료이며 추가 설정 절차가 아닙니다.

## 범위

- **버전:** Codex CLI **0.154.0**과 `@github/copilot-sdk` **1.0.14**로 확인했습니다. 새 버전은 adapter 변경이 필요한 필드나 도구를 추가할 수 있으므로, 새 프로토콜을 확인하기 전까지는 고정 버전을 유지하세요.
- **증거:** 오프라인 검사는 모의 SDK 응답으로 bridge를 검사합니다. 실제 모델의 동작은 [기록된 실모델 실행](validation/README_KO.md#기록된-결과)만 보여 줍니다.
- **모델:** [지원 모델 6개](../README_KO.md#모델)의 ID만 문서화된 선택 화면 순서로 허용하며, 실제 사용 가능 여부는 계정 정책이 정합니다. 퇴역한 모델을 포함한 다른 ID는 거절합니다. ID는 공급자 간 이름 변환이나 대체 없이 그대로 SDK에 전달합니다.

## 구현한 동작

- **경로:** JSON 또는 HTTP/SSE 텍스트 출력의 `POST /v1/responses`, 인증이 필요한 `GET /v1/models`·`GET /readyz`, 공개 `GET /health`.
- **입력:** 텍스트 메시지, 전달된 대화 어디에나 있는 system·developer 지시문, 클라이언트 function 도구, custom(freeform) 도구.
- **도구 선언:** Codex 도구 namespace와 `additional_tools`. function 인자는 JSON 의미를, custom 도구 입력은 원래 문자열을 유지합니다.
- **도구 결과:** 여러 대기 호출을 동시에 처리하며, 모든 출력을 담은 다음 배치 하나로 응답받습니다.
- **`parallel_tool_calls=false`:** 응답마다 호출을 최대 하나만 전달합니다. SDK가 호출을 여러 개 내보내면 하나도 전달하지 않고 `parallel_tool_calls_violation`으로 턴을 실패시킵니다. 출력을 검사할 뿐 모델의 생성 방식을 바꾸지는 않습니다.
- **대화 상태:** 살아 있는 전체 이력의 접두 일치, 대화별 요청 하나씩 처리, 실행 중인 프로세스 안에서의 `previous_response_id` 이어가기.
- **캐시 재시도:** 가장 최근에 성공한 정규화 요청의 동일한 재시도는 해당 대화 상태가 살아 있고 유효할 때만 캐시를 반환합니다. 실패한 요청·제거된 상태·bridge 재시작에는 이 캐시가 없으며 일반적인 정확히 한 번 실행 보장이 아닙니다.
- **한도:** 클라이언트 취소, SDK 제한 시간, 제한된 메모리 상태, 유휴·초과 대화 제거.
- **추론 수준:** 선택한 모델의 catalog가 지원할 때만 적용합니다. Haiku 4.5는 추론 수준을 설정할 수 없습니다.
- **모델 목록과 문맥:** 실행기가 소유하는 선택 화면 catalog, 가장 큰 tier 기준의 입력 예산, 완전한 도구 결과 전달 후의 네이티브 로컬 자동 압축. `npm run test:runtime`은 실제 Codex CLI와 가짜 SDK로 이를 검사하며, 최대 문맥이나 장시간 추론을 검사하지는 않습니다.

## 정확히 같지 않은 부분

아래 항목은 동작하지만 네이티브 OpenAI Responses API와 똑같지는 않습니다.

- **custom grammar:** custom 도구는 필수 `input` 문자열 하나를 가진 SDK JSON-schema 도구가 됩니다. grammar는 모델에 대한 안내로 전달하며 decoder가 강제하지 않습니다. 반환된 원문 입력의 해석과 실행은 계속 Codex가 담당합니다.
- **이력 재생:** 새 SDK 세션은 임의의 Responses 대화를 원래 role 그대로 가져올 수 없으므로, 완료된 이전 턴을 프롬프트 문맥으로 직렬화합니다. 대화가 살아 있고 일치하는 동안에는 SDK 세션을 유지하고 실제 대기 도구 결과를 제출합니다.
- **지시문:** SDK 자체의 system·안전 지시문은 그대로 유지합니다. 요청 지시문과 대화 중간에 있는 것을 포함한 모든 최상위 system·developer 메시지를 변경 없이 추가합니다(`systemMessage.mode="append"`, `replace`는 사용하지 않음). 두 role은 같은 SDK 필드를 공유합니다. role을 보존하는 범용 대화 가져오기가 없으므로 이전 user·assistant 메시지에는 여전히 직렬화 재생이 필요합니다.
  - 변경되지 않은 살아 있는 세션에서는 대기 결과와 함께 온 새 user 메시지를 SDK의 별도 즉시 조정(immediate steering)으로 보내며, 도구 출력에 덧붙이지 않습니다.
  - 모든 대기 결과와 함께 온 신뢰할 수 있는 지시문 변경은 정리를 확인한 뒤 세션을 다시 만듭니다. 지시문의 권한은 유지되고 도구 출력은 직렬화 이력에서 바이트 단위로 보존됩니다. 불완전하거나 바뀐 대화 입력은 이전 세션을 종료하기 전에 실패합니다.
  - SDK 내장 도구는 계속 사용할 수 없습니다. 클라이언트 도구는 Codex만 자신의 샌드박스·승인 정책으로 실행합니다. [핸드오프 절차](ARCHITECTURE_KO.md#완료된-도구-결과와-함께-설정-바꾸기)를 참고하세요.
- **assistant phase:** `commentary`와 `final_answer`는 [Responses phase 의미](https://developers.openai.com/api/docs/guides/reasoning#phase-parameter)에 따라 정규화와 재생 후에도 유지됩니다. 생략된 이전 phase는 알려진 값을 재사용하고, 명시적으로 바뀐 phase는 살아 있는 접두 일치를 무효화합니다.
- **완료 시점:** 텍스트 응답은 루트 `session.idle`에서 끝나므로 뒤늦은 수정·usage·오류도 도착할 수 있습니다. 도구 응답은 모든 대기 외부 호출의 상관관계가 확인되면 끝납니다. 도구 호출 없는 빈 응답과 맞지 않는 대기 호출은 성공으로 저장하기 전에 실패합니다.
- **usage:** 가능하면 실제 SDK 토큰 수를 반환하며, 없으면 추정하지 않고 `null`로 둡니다. usage·캐시·과금은 Copilot의 규칙을 따르며 OpenAI와 같지 않을 수 있습니다.
- **영속성:** 응답 추적 정보는 메모리에만 있습니다. 재시작·TTL 만료·용량 초과 제거는 응답 ID와 미해결 호출을 무효화합니다. `store:false`는 Codex나 SDK의 로컬 파일 기록을 막지 않으며 Copilot의 데이터 미보관을 약속하지 않습니다.
- **reasoning summary:** SDK 세션 생성과 모델 설정 변경에 `reasoningSummary: "none"`을 명시해 summary를 끈 실행기 설정과 맞춥니다. 요청한 추론 수준은 따로 유지합니다. 설정 일관성을 위한 것이며 상위 서비스 거절의 알려진 원인이나 해결책이 아닙니다.

## 거절하거나 비활성화하는 기능

- WebSocket 전송, 압축된 요청, 원격 Responses 압축.
- 모델 입력으로서의 이미지·오디오·영상·파일, 텍스트가 아닌 도구 출력.
- 공급자 호스팅 웹 검색, code interpreter, file search 등 서버 측 내장 도구.
- 엄격한 도구 스키마 강제, 구조화 JSON 출력, 필수·지정 도구 선택.
- temperature, top-p, 명시적 출력 토큰·도구 호출 제한, 자동 요청 절단.
- reasoning summary, 암호화된 reasoning 재생, 영구 응답 조회, 저장·백그라운드 Responses 작업, 사용자 지정 service tier.

실행기는 호환되지 않는 전송·검색 기능을 끕니다. 지원하지 않는 다른 기능은 동작하는 척하지 않고 명시적인 오류로 실패합니다. 캐시 키, 메타데이터, 텍스트 상세도, 암호화된 reasoning 포함 요청 같은 Codex의 정보성 힌트는 무시했다고 로그에 남을 수 있으며, 해당 기능을 추가하지는 않습니다.

Codex 0.154는 thread의 첫 프롬프트 뒤에 짧은 작업 제목을 만들기 위한 요청을 하나 더 보내며, 이 요청은 JSON 스키마를 사용합니다. bridge는 HTTP 400(`Structured output is not supported`)으로 거절하고, Codex는 제목 없이 정상적으로 계속합니다.

## 상위 서비스에서 필터링한 응답

루트 SDK `assistant.usage` 이벤트가 `contentFilterTriggered=true` 또는 `finishReason="content_filter"`를 보고하면, bridge는 요청을 `upstream_content_filter`로 실패시킵니다. 거절처럼 보이는 문구가 아니라 이 구조화된 메타데이터로만 판단합니다.

- JSON 요청은 HTTP 422를 받습니다. 이미 시작된 SSE 스트림은 HTTP 200 헤더를 유지하지만 `response.completed`가 아니라 `response.failed`로 끝납니다.
- 그 턴의 어떤 결과도 성공이나 대기 호출로 저장하지 않으며, 실패한 세션 상태와 응답 참조는 무효화합니다. bridge는 필터를 끄거나 추론을 재시도하거나 도구 결과를 다시 제출하지 않습니다. 이미 전달한 부분 텍스트는 미완료로 표시하며 되돌릴 수 없습니다.
- 구조화된 필터 메타데이터가 없는 거절처럼 보이는 텍스트는 일반 모델 출력으로 남습니다. 하위 agent의 메타데이터는 루트 응답을 대체하지 않습니다.
- 필터 감시는 도구 전달 후와 유휴 상태에서도 계속됩니다. 뒤늦은 루트 신호는 다음 캐시 재시도나 대기 결과 이어가기를 무효화하지만, 이미 전달한 출력은 되돌릴 수 없습니다. 이후 SDK 종료 오류가 나도 처음 관측한 장애를 유지합니다.

이 동작은 오류를 명시적으로 알릴 뿐 공급자가 거절한 이유를 설명하지 않습니다. 지원하는 턴이 필터링되면 [핵심 연동 검사](VERIFICATION_KO.md)에서도 실패입니다. 거절 문장만으로 공급자 내부 원인을 단정하지 마세요.

## 운영 시 주의

- **모델:** 시작 모델은 `--ghcp-model`로 선택합니다. `/model`은 허용된 6개 모델 중 계정에서 사용할 수 있는 모델을 고정 순서로 보여 줍니다. 임시 catalog는 Codex 설정을 수정하지 않지만, Codex가 `/model` 선택을 `~/.codex/config.toml`에 저장할 수 있습니다. [선택과 저장](USAGE_KO.md#모델-선택과-문맥)을 참고하세요.
- **도구 결과:** 결과 배치에는 대기 중인 모든 호출이 정확히 한 번씩 있어야 합니다. 완료된 호출 ID와 오래된 응답 버전은 기억하며 이전 결과 RPC는 다시 제출하지 않습니다. 직렬화한 이력만으로는 모델이 새 ID로 같은 작업을 다시 요청하는 것을 막을 수 없습니다.
- **설정 변경:** 호출이 대기 중일 때의 변경(도구 없는 압축 포함)에는 지시문 이외의 이력이 바뀌지 않은 완전한 결과 전달과, 확인된 정리·준비 상태가 필요합니다.
- **문맥:** SDK 세션은 가장 큰 문맥 tier(가능하면 `long_context`, 아니면 `default`)를 사용하고, Codex는 catalog 입력 예산의 80%에서 압축합니다. 문맥 초과는 `context_length_exceeded` 코드를 유지합니다.
- **제한 시간과 재시도:** 첫 진행에는 별도로 180초를 주고 그다음에는 90초 스트리밍 무응답 제한을 적용하며, 둘 다 턴·요청 전체 제한 안에서 동작합니다. 실행기는 HTTP·스트림 자동 재시도를 끕니다.
- **분기:** 최신 성공 결과는 해당 상태가 유효할 때 재시도할 수 있지만 임의의 이전 응답 분기는 이어갈 수 없습니다. 분기하려면 전체 이력으로 새 대화를 시작하세요.
- **승인:** Codex의 일반 샌드박스·승인 동작을 유지하며, bridge는 승인 우회 옵션으로 대체하지 않습니다.
- **상주 bridge:** 기본 등록 정보는 작업 프로젝트 간에 공유하며 bridge를 시작한 clone에 묶입니다. 상태 확인·중지는 자신이 소유한 bridge 인스턴스를 확인합니다. [재사용과 격리](USAGE_KO.md#선택적-상주-bridge)를 참고하세요.
