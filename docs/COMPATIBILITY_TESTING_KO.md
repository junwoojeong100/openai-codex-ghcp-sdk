# 개발 워크플로 호환성 검사

[English](COMPATIBILITY_TESTING.md) · [검증 안내](../README_KO.md#개발과-검증) · [시나리오 사양](NATIVE_SCENARIOS_KO.md) · [제품 경계](COMPATIBILITY_KO.md)

실제 개발 워크플로를 Codex와 bridge로 실행해 검사합니다. **18개 시나리오 × 6개 모델 = 108건**이며, 실모델 실행은 **108/108**일 때만 통과입니다. 안정성·TUI 결과는 여기에 포함하지 않습니다. 실행기를 쓰는 데 이 검사는 필요하지 않습니다.

현재 검사 사양(버전별 시나리오·통과 기준)은 `codex-ghcp-workflows-18-v6`이며 보고서의 `schemaVersion`은 6입니다. 한 케이스는 한 모델에서 시나리오 하나를 실행한 결과이며, 전체 목록은 [시나리오 사양](NATIVE_SCENARIOS_KO.md#시나리오-목록)에 있습니다.

**바로가기:** [실행](#검사-실행) · [결과 읽기](#결과-읽기) · [통과 기준](#통과-기준) · [지표](#서로-다른-세-지표) · [검사 경로](#검사하는-네이티브-경로) · [증거 규칙](#증거-규칙) · [v6 변경](#v6-러너-변경)

## 검사 실행

모든 명령은 `npm ci` 후 저장소 루트에서 실행합니다. 각 모드는 단독으로 실행할 수 있으니 목적에 맞는 것을 고르세요.

| 목적 | 모드 | 실모델 호출 |
| --- | --- | --- |
| 검사 사양 확인·시나리오 설계 검사 | [계획](#계획) | 없음 |
| 실제 Codex로 러너 확인 | [오프라인 runtime](#오프라인-runtime) | 없음 |
| 108건 전체 측정 | [실모델 행렬](#실모델-행렬) | **있음** |
| 끝난 실행 다시 확인 | [보고서 검증](#보고서-검증) | 없음 |

### 계획

Codex 설치나 Copilot 로그인이 필요하지 않습니다. 케이스를 실행하지 않고 108건 검사 사양을 출력합니다.

```bash
npm run test:compatibility -- --plan
```

시나리오 설계는 `npm run test:scenarios`로 검사합니다. 문서만 바꿨다면 `npm run test:docs`로 충분합니다. 예시를 실행하지 않고 안내 문서·명령 예시·생성된 시나리오 문서를 검사합니다.

### 실행 준비 사항

오프라인 runtime과 실모델 행렬에는 Node 22.12 이상, Codex **0.154.0**([설치 단계](../README_KO.md#2-의존성-설치)), 동작하는 OS 샌드박스가 필요합니다. 브라우저는 필요하지 않으며 Copilot 로그인은 실모델 행렬에만 필요합니다. 일반 실행에는 이보다 완화된 [준비 사항](../README_KO.md#준비-사항)이 적용됩니다.

### 오프라인 runtime

실제 Codex를 격리된 인증정보와 SDK 대역(Copilot SDK 대신 동작하는 로컬 구현)에 연결해 실행하며, C11에서는 실제 실행기도 사용합니다. 모델을 호출하지 않습니다.

```bash
npm run test:compatibility:runtime
```

러너를 확인한 결과이며 실모델 호환성 통과가 아닙니다.

### 실모델 행렬

**Copilot 사용량이 발생합니다.** OpenAI API 키는 필요하지 않습니다.

1. [실행 준비 사항](#실행-준비-사항)을 설치하고 [Copilot 계정 확인](../README_KO.md#3-설치와-계정-접근-확인)을 마칩니다.
2. `./bin/ghcp-models`를 실행해 **[지원 모델 6개](../README_KO.md#모델) 모두** 사용할 수 있는지 확인합니다. 로그인만으로는 모델 접근이 확인되지 않습니다.
3. **정확한 소스와 `package-lock.json`의 사본을 저장합니다.** 안정성·TUI 러너와 달리 이 러너는 자신의 소스를 저장하지 않습니다. 보고서를 검증할 때까지 소스를 바꾸지 마세요.
4. 새 출력 디렉터리를 지정해 행렬을 실행합니다.

```bash
npm run test:compatibility -- --execute --output .runtime/compatibility-new-run
```

러너는 기존 출력 디렉터리를 덮어쓰지 않습니다. 최악의 경우 약 **75.5분**이 걸립니다([소요 시간](#소요-시간)).

### 보고서 검증

검증은 저장된 증거로 모든 판정을 다시 계산합니다. 모델을 호출하거나 케이스를 다시 실행하지 않습니다. 실패가 있어도 끝난 실행은 모두 검증하세요.

```bash
npm run test:compatibility -- --verify .runtime/compatibility-new-run/report.json
```

검증은 별도 명령으로 실행하세요. 실패가 있는 실행은 종료 코드 1로 끝나므로 `--execute` 뒤에 `&&`로 `--verify`를 연결하면 검증이 건너뛰어집니다.

**실행 후 소스가 바뀌었다면** 3단계에서 저장한 사본을 사용하세요. 실행 디렉터리 전체를 보존하고, 의존성을 설치한 사본의 루트에서 원래 보고서의 **절대 경로**로 저장된 러너를 실행합니다.

```bash
node scripts/compatibility.mjs --verify /absolute/path/to/compatibility-run/report.json
```

일치하는 소스와 원본 증거가 없으면 결과를 다시 계산할 수 없습니다. [검증 기록](validation/README_KO.md)에 공개한 요약은 완전한 보고서가 아니므로 `--verify`에 넣지 마세요. 과거 v5·v4 보고서에는 v6가 아닌 당시 러너가 필요합니다.

## 결과 읽기

출력 디렉터리의 `report.md`(예: `.runtime/compatibility-new-run/report.md`)를 여세요. 읽는 순서대로 구성되어 있습니다.

1. **Result:** 판정과 모델별 통과 수
2. **Cases needing attention:** 실패한 판정, 기록된 오류, 케이스 증거 링크
3. **Complete matrix:** 108건 전체
4. 결과 다음의 **커버리지 설명**

`report.md`는 읽기용 보기일 뿐이며 `--verify`는 `report.json`을 검사합니다. 보고서의 `executionKind`로 오프라인·실모델 실행을 구분합니다.

| 종료 코드 | 의미 |
| --- | --- |
| 0 | 유효한 계획, 오프라인 self-test 통과, 또는 실모델 108건 전체 통과 |
| 1 | 실패·차단·미지원·미완료 실행 |
| 2 | 인자 또는 증거 오류 |

**`evidenceIntegrity: true`는 108/108 통과를 뜻하지 않습니다.** 검증기가 저장된 증거를 받아들이고 결과를 다시 계산했다는 뜻입니다. 판정은 `fullMatrixPassed`로 확인하세요. [보고서 필드 해석](validation/README_KO.md#결과-읽기)을 참고하세요.

## 통과 기준

- **108건이 모두 통과해야 합니다.** 누락·미지원·차단·시간 초과 케이스도 분모에 남습니다. 사용할 수 없는 모델의 18건은 차단으로 남고, 공통 사전 조건이 실패하면 108건 모두 남습니다.
- **모델별로 워크플로 18개가 모두 통과해야** 호환으로 판정합니다.
- **다시 기회를 주지 않습니다.** 모델 부분 선택·자동 케이스 재실행·OpenAI 기준선은 없습니다. 실패한 케이스가 이후 케이스를 건너뛰게 하지 않으며, 실패는 점수를 올리려고 다시 실행하지 않고 보존합니다.
- **한 실행에는 한 구현만:** 실모델 실행 전에 catalog·구현 hash를 고정합니다. 실행을 중단하면 이후 일정은 멈추지만 미완료 증거는 남습니다.
- **오프라인은 실모델이 아닙니다.** 오프라인 실행은 실모델 기능 증거가 되지 않습니다.

## 서로 다른 세 지표

세 수치는 서로 다른 질문에 답하므로 섞지 마세요.

| 지표 | 계산 / 값 | 의미 |
| --- | --- | --- |
| 실모델 행렬 통과율 | 통과 / **108**, 모델별 통과 / **18** | 관측한 결과입니다. 누락·미지원·차단·시간 초과 케이스도 분모에 남습니다. |
| 체크리스트 설계 범위 | 기능군 20개 중 직접 12 + 절반 점수 6 + 미검증 2 = **75%** | 검토자가 정한 설계의 폭입니다. 검사 결과나 전체 기능 지원 비율이 아닙니다. |
| 실측 제품 커버리지 | **미측정/null**, 90%는 목표 | 위 두 수치로 측정되지 않습니다. 체크리스트는 공식·사용 빈도 기반 지원 지표가 아닙니다. |

보고서는 모델별 기능군 증거도 표시합니다. 일부만 다루는 기능군은 연결된 시나리오가 모두 통과해도 부분 범위로 남습니다.

## 검사하는 네이티브 경로

- **C11:** 실제 `bin/codex-ghcp`, 운영 bridge 수명주기, 기본 도구 카탈로그. `model_catalog_json`이나 patch 프로필을 주입하지 않습니다. 대화형 `/model`이나 모든 추론 수준을 인증하지는 않습니다.
- **C12:** 네이티브 `review/start`와 reviewer 수명주기. 리뷰처럼 보이는 일반 프롬프트로 대체하지 않습니다. 네이티브 reviewer에 bridge가 지원하지 않는 구조화 출력이 필요하면 통과가 아니라 **unsupported**입니다.
- **C13:** 네이티브 Plan 협업 모드와 상관관계가 확인된 사용자 입력 callback. 모델에 알려주지 않은 호스트 응답이 파일 변경 없이 최종 계획에 반영되어야 합니다.
- **C14:** 12 KiB 이상 이력, 명시적 네이티브 로컬 압축, 새 프로세스 재개. 최대 문맥·자동/원격 압축·soak 인증이 아닙니다.
- **C15:** 실행 중인 소유 명령을 관측한 뒤 중단하고, 백그라운드 터미널을 명시적으로 정리해 프로세스 종료를 증명한 다음 같은 thread에서 계속합니다.
- **C16:** 소유 Streamable HTTP MCP endpoint, 임시 bearer 인증, 인증 없는 요청 거절, 발견·리소스, 오류 복구. 외부 OAuth나 플러그인 설치 검증이 아닙니다.
- **C17:** 읽기 전용 자식 하나의 네이티브 spawn·wait·close 수명주기와 별도 thread·SDK 세션.
- **C18:** 추론 전에 표시된 503 한 건, 제한된 네이티브 HTTP 재시도 한 번, SDK 프롬프트·도구 중복 실행 없음. 실패 케이스 재실행이나 스트림 중간 재시도가 아닙니다.

시나리오별 규칙:

- **C03**은 필드 자료형을 명시하고, JSON 의미를 표현 형식(bare JSON 또는 단일 JSON fence)과 분리해 검사합니다. `git -c ... diff`도 diff로 인정합니다.
- **C05**는 파이프 없는 독립 테스트 명령을 요구하므로 파이프라인이 실패 종료 코드를 가릴 수 없습니다.
- **도구 호출 목표 횟수**는 효율 진단입니다. 별도의 더 높은 상한이 폭주 실행을 멈추고 케이스를 실패시킵니다.

## 증거 규칙

### 실행 전에 고정한 해석

- **C12**는 완료된 네이티브 리뷰의 렌더링된 finding 또는 JSON을 읽습니다. `review.mjs:3`의 실제 결함 정확히 한 건, 실제 diff 읽기, 상관관계가 확인된 reviewer 수명주기, 파일 보존이 여전히 필요합니다.
- **C13**은 부수적인 assistant 메시지가 아니라 완료된 네이티브 `plan` 항목을 판정합니다. 숨은 호스트 응답의 상관관계가 확인되고 최종 계획에 나타나야 합니다. 읽기 전용 탐색만 허용하며 편집·변경 명령·광범위한 권한 부여는 허용하지 않습니다.
- **Git diff 증거**는 묶인 셸 명령과 Git 전역 옵션을 인식하지만, 인용된 `git diff` 문자열은 실행 증거가 아닙니다. 음성 테스트는 다른 경로·턴, 추가 finding, 누락된 diff, 상관관계가 없거나 안전하지 않은 계획을 거절합니다.

이 C12·C13·Git 규칙은 v4에서 고정해 v6에도 그대로 적용하며, 실행 후 추가한 예외가 아닙니다. C05 명령과 C15 host PID 변경은 [v6 러너 변경](#v6-러너-변경)에 설명합니다.

### 격리

- 모든 fixture는 전용 임시 HOME과 변경을 허용하는 파일의 명시적 목록을 사용하며, 사용자 dirty 파일·Git index·HEAD를 보존합니다.
- 네이티브 셸 환경에는 upstream 인증을 전달하지 않습니다.
- 알 수 없는 callback은 거절합니다. 정확한 소유 승인 helper와 범위가 제한된 fixture MCP 동작만 승인할 수 있습니다. 사용자 입력 응답은 C13 fixture 질문에만 제공합니다. 포괄 승인이나 외부 OAuth 권한 부여는 없습니다.
- 실모델 모드에서 C11 관찰 계층은 운영 인자·메타데이터를 바꾸지 않고 실제 SDK·HTTP 경계를 기록합니다. SDK 교체는 오프라인 모드만 허용하며, 검증기가 사용된 모드를 확인합니다.
- 임시 MCP 인증정보는 헤더나 증거에 남기지 않습니다. 소유 프로세스·서버·SDK 세션은 반드시 정리해야 합니다.

### 저장되는 증거

보고서는 native JSONL, HTTP/SSE, SDK, 상태, 판정, 정리, 시나리오별 증거를 보존합니다. 검증은 검사 사양·구현 hash, 모든 행렬 칸, 증거 파일의 소유·hash를 확인하고 판정과 지표를 다시 계산합니다. hash는 파일을 식별할 뿐 제3자 인증이 아닙니다. 원시 증거는 Git에서 제외한 `.runtime` 디렉터리에 둘 수 있으며, 공개하기 전에 개인정보를 검토하세요.

## 소요 시간

- 최대 4개 모델을 동시에 실행하며, 각 모델의 케이스는 순서대로 실행합니다.
- 각 케이스 제한에는 정리 예비 시간 8초가 포함됩니다.
- 모든 케이스가 제한을 다 쓰면 모델 하나에 2,220초, 전체 실행에 약 **75.5분**이 걸립니다. 사전 점검은 포함하고 OS·I/O 부하는 제외한 값입니다.
- 1시간은 목표이며 전체 강제 종료 시간이 아닙니다.

## v6 러너 변경

v6는 OS 샌드박스를 완화하지 않고 Linux 검증의 세 가지 가정을 바로잡습니다.

- **C05**는 `node --test --experimental-test-isolation=none`을 실행해 변경할 수 없는 같은 테스트 3개를 한 Node 프로세스에서 실행합니다. 고정 버전 샌드박스에서 자식 프로세스의 캡처된 stdio가 사라지는 문제([상위 이슈](https://github.com/openai/codex/issues/18473))를 피합니다. 실제 실패·성공 종료 코드, 테스트 3개 전체, 독립 입력 검사는 그대로 요구합니다.
- **C08**은 바꾸지 않은 측정값을 문제가 되는 Node 스트림 대신 stdout 파일 디스크립터에 직접 기록합니다.
- **C15**는 receipt의 namespace PID를 같은 작업 디렉터리에 있는 소유 native host의 고유한 자손 프로세스와 연결한 뒤 host 프로세스 종료를 확인합니다. 샌드박스 PID를 전역 PID로 가정하지 않습니다.

과거 실패 기록은 바꾸지 않습니다.
