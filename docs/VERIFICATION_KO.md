# 검증 안내

[English](VERIFICATION.md) · [빠른 시작](../README_KO.md) · [현재 결과](validation/README_KO.md)

**단일 기준은 `codex-ghcp-essential-v1`입니다. 핵심 시나리오 6개 × 모델 6개 = 36건이며 36/36만 통과입니다.** 선택형 문구 프로필·백분율 목표·별도 실모델 행렬은 없습니다.

## 실행

저장소 루트에서 `npm ci` 후 Node 22.12 이상·Codex **0.154.0**·Python 3·macOS/Linux를 사용합니다. Chromium은 한 번만 설치하세요.

```bash
npx --no-install playwright install chromium
```

Linux에서 시스템 라이브러리가 부족하면 `npx --no-install playwright install --with-deps chromium`을 사용합니다. [Copilot 계정 확인](../README_KO.md#3-설치와-계정-접근-확인)을 마치고 모델 6개 모두 사용 가능한지 확인하세요. OpenAI 키는 필요하지 않습니다.

**실제 Copilot 모델을 호출하며 사용량이 발생합니다.**

```bash
npm run verify -- --execute --output .runtime/verification-new
```

새 출력 디렉터리를 사용하세요. 기존 결과는 덮어쓰지 않습니다. `--output`을 생략하면 새 경로를 자동으로 선택합니다. `npm run verify`만 실행하면 모델 호출 없이 계획만 표시합니다.

명령 하나가 케이스 실행·증거 저장·**결과 자동 재계산**을 마치고 `report.md` 경로를 출력합니다. 판정과 실패 케이스를 읽으면 됩니다. 종료 코드 **0**은 36건 전체 통과, **1**은 실패·차단·미완료, **2**는 인자·증거 오류입니다. 프로세스를 모두 정리했더라도 작업 실패가 통과로 바뀌지는 않습니다.

## 남긴 핵심 검사

| ID | 시나리오 | 필요한 증거 |
| --- | --- | --- |
| V01 | CLI/TUI 실행·유니코드 대화·`/new` 격리 | 실제 `codex exec --json` 응답, 모델 6개 피커, 유니코드 응답, 이전 표지가 없는 새 대화 |
| V02 | 파일 읽기·코드 수정·테스트 | 읽기 전용 진단에서 실제 테스트 실패·파일 불변을 확인한 뒤에만 같은 대화에서 native `apply_patch`와 동일 테스트 3개 통과 요청 |
| V03 | MCP 오류·결과 연결 | Codex 소유 MCP의 ENOENT 결과 이후 성공 결과와 올바른 후속 응답 |
| V04 | 모델·추론 수준 전환 | 피커의 선택이 다음 실제 응답에 반영됨. High 추론 수준 또는 Haiku에서 추론 설정이 없는 상태 |
| V05 | 중단 후 계속 | SDK 전송을 관측한 뒤 Escape로 해당 세션의 실제 턴 중단, 같은 네이티브 프로세스의 다음 응답 |
| V06 | 압축·재개 | 로컬 `/compact`, 회상, 정상 종료, `resume --last`로 새 bridge 실행, 저장 이력의 새로운 회상 응답 |

V02는 모든 모델에서 **읽기 전용 진단 → 수정**의 두 턴으로 진행합니다. 네이티브 테스트 실패와 작업 공간 불변을 기록해야만 수정 요청을 전달합니다. 실패 재현 누락·조기 수정·종료 코드 은폐는 즉시 실패하며, 이를 보정하는 추가 지시나 시나리오 재시도는 하지 않습니다. 최종 근거에도 같은 진단 기록이 앞부분에 그대로 남고 이후 동일 테스트 3개가 통과해야 합니다. 단계별 코딩 절차를 검증하는 것이며 복합 요청 한 번의 지시 준수를 보장하지는 않습니다.

여기서 "읽기 전용"은 첫 턴의 지시이며 샌드박스 전환이 아닙니다. V02 두 턴 모두 같은 격리된 `workspace-write` 샌드박스를 사용합니다. 단계 전환 조건은 기록된 도구 활동과 작업 공간 스냅샷을 확인하는 것이며, 파일 쓰기 차단이나 지속적인 파일 변경 감시는 아닙니다.

V02는 셸 표현 방식이 아니라 실제 테스트의 실패·성공 요약과 네이티브 종료 코드를 검사합니다. 테스트가 마지막 명령이면 앞에 읽기 전용 준비 명령(`echo`/`printf` 표지 포함)이 있어도 인정합니다. 파이프·종료 코드 가림·가짜 테스트 출력은 인정하지 않습니다. 완료된 도구 호출 응답은 핸드오프이지 최종 답변이 아닙니다. 검증기는 완료된 텍스트 응답, 새 턴의 ID가 일치하는 네이티브 `task_started`·`task_complete` 기록, 준비된 입력창을 모두 확인해야 다음 단계로 넘어갑니다. 화면에 답변이 보인다는 이유만으로 `/compact`가 가능한 것은 아니며, 압축 명령이 거절되면 재시도 없이 실패합니다.

모든 실모델 케이스는 **실제 Codex → 운영 bridge → 실제 GitHub Copilot SDK → 정확한 Copilot 모델**을 거칩니다. 비대화형 CLI와 대화형 TUI 실행을 모두 확인합니다. HTTP/SSE·정확한 모델 라우팅·문맥/감시 설정·작업 공간 보호·Copilot 런타임 MCP 격리·정리도 확인하며, TUI는 전용 PTY와 headless Chromium에서 구동합니다. 모델 출력을 고치거나 대신하지 않으며 거절·누락된 도구 작업·정리 오류·시간 초과는 실패입니다. 정확히 식별한 미지원 자동 제목 요청만 별도 집계하며 성공 응답으로 인정하지 않습니다.

모든 케이스는 격리된 Codex 홈·작업 공간과 운영 기본 제한 시간을 사용합니다. 인증은 기존 Copilot 홈을 사용하므로 데이터가 전혀 기록되지 않는 환경은 아닙니다. 검증기는 사용자 설정 불변을 확인하며 기존 사용자 bridge를 재시작하지 않습니다. 모델 3개를 병렬로 진행하되 각 케이스의 제한 시간은 고정돼 있습니다. 자동 케이스 재시도·대체 모델·부분 집합·다른 실행 점수 합산은 없습니다. `Ctrl+C`는 소유한 작업만 중단하고 미완료 보고서를 남깁니다.

검증 실행은 CLI 버전을 고정하므로 `-c check_for_update_on_startup=false`를 전달합니다. 새 프로세스로 재개할 때 캐시된 업데이트 안내가 입력창을 대신하지 않도록 하기 위한 설정입니다. 번호가 붙은 메뉴 항목은 입력창으로 인정하지 않으며, 예상 밖의 업데이트 팝업은 아무 항목도 선택하지 않고 실패합니다. 검증·오프라인 fixture에만 적용하며 일반 실행기 동작이나 사용자·전역 설치는 바꾸지 않습니다.

운영 bridge의 복구는 시나리오 재실행이 아닙니다. 복구된 전송 오류도 원본 근거에 남기며, 같은 세션의 abort·disconnect·delete 기록, 안전한 복구 진단, 원래 응답 ID의 정상 완료가 모두 일치해야만 인정합니다. 기록 누락·불일치, 필터링, 실패한 스트림은 여전히 실패입니다. 보고서는 전송 오류 복구와 시작 시 목록 조회 복구 횟수를 별도로 표시합니다.

## 로컬 회귀 검사

`npm test`는 모델 호출 없이 운영 프로토콜·인증·상태·대기열·재전송 방지·취소·필터링·증거 규칙을 검사합니다. `npm run test:runtime`은 같은 핵심 드라이버 6개를 SDK 대역으로 실행하고, 필요한 네이티브 문맥·시간 제한·핸드오프 회귀 검사도 수행합니다. 핸드오프를 포함해 항상 오프라인이며 별도 실모델 버전이나 점수가 아닙니다.

CI는 Linux와 macOS의 단위/커버리지·오프라인 runtime을 대상으로 설정돼 있으며 실모델 행렬은 실행하지 않습니다. 이 설정 자체가 원격 CI 성공의 근거는 아닙니다. `npm run test:docs`는 현재 문서 링크·명령·한영 명령 일치를 검사하고, `npm run test:ci`는 단위 검사와 커버리지를 실행합니다. 생성형 시나리오 문서나 별도 시나리오 설계 검사 명령은 필요하지 않습니다.

## 저장되는 증거

각 TUI 실행은 실제 Chromium의 `terminal-browser.webm`, 종료 화면, 실행·응답·모델 선택·중단·압축 단계의 PNG를 기록합니다. 단계별 텍스트와 대략적인 영상 시점으로 장면을 찾을 수 있으며 결과 재검사 시 파일 해시도 확인합니다. 실모델 녹화는 실제 대기와 결과를 담고 모델 출력을 모사하지 않으며, 오프라인 runtime 검사는 같은 녹화 기능에 SDK 대역을 사용합니다. 원본에는 로컬 경로나 오류 세부 정보가 보일 수 있으므로 공유 전에 확인하세요. 공개 요약 영상에는 편집 사실을 표시해야 하며 전체 근거나 36개 판정을 대신하지 않습니다.

출력 디렉터리에는 `report.md`, `report.json`, `verification.json`, 케이스별 fact·정리 기록·`source-snapshot/`이 자동 저장됩니다. 확인 응답을 기억할 데이터와 혼동하지 않고 회상 실패를 조사할 수 있도록 압축 요약도 일반 답변과 함께 로컬에 보존합니다. 실행 직후 추가 명령은 필요하지 않습니다. 나중에 보존된 실행을 모델 호출 없이 확인하려면:

```bash
npm run verify -- --verify .runtime/verification-new/report.json
```

소스가 바뀌었다면 실행 당시 저장한 검증기와 일치하는 의존성을 사용합니다.

```bash
node .runtime/verification-new/source-snapshot/scripts/verify.mjs --verify .runtime/verification-new/report.json
```

`evidenceIntegrity: true`는 저장된 해시 일치와 fact 기반 판정 재계산을 뜻하며, 동작 통과나 외부 서명을 뜻하지는 않습니다. `fullMatrixPassed: true`는 별도로 전체 36건과 실행 수준 검사를 요구합니다. 구현 지문에는 실행·검증·테스트 파일과 패키지 manifest가 포함되지만 설명 문서는 포함되지 않습니다. 원본 근거는 Git에서 제외하므로 위 재검사 명령에는 원래 로컬 실행 폴더가 필요하며, 새 clone의 공개 JSON·미디어로 대체할 수 없습니다.

## 보존과 범위

현재 검증 기준과 최신 전체 실행·해당 미디어만 보존합니다. 보존된 원본은 `.runtime/verification-final/`, 공개 요약·선별 미디어는 `docs/validation/`에 있습니다. 검증기는 항상 새 디렉터리를 만들며 다른 실행을 자동으로 삭제하거나 공개 요약·편집 영상을 다시 생성하지는 않습니다.

이 기준의 통과는 네이티브 리뷰·Plan·서브에이전트·skill 전체, 모든 장애 조합, 대용량 입력, 5시간 운용, 최대 문맥 추론이나 [미지원 기능](COMPATIBILITY_KO.md)을 인증하지 않습니다. 핵심 연동 결과이지 제품 전체 완성도 백분율이 아닙니다.
